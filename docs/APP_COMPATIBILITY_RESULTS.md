## TLS 1.3 download defect: FIXED after this run (UI path hardware-tested 2026-11-09)

When this run was made RetroHatch's downloader (mbedTLS 2.16) spoke TLS 1.2 at most and `static.miraheze.org`, where the FunKey wiki hosts its OPKs, only accepts TLS 1.3, so Test Install failed with "TLS handshake failed" for 28 candidates (3DOh, Commodore 64, Dinothawr, DOSBox Pure, EasyRPG, Fake-08, FinalBurn Alpha 2012, FinalBurn Neo, Gambatte, Game Music Emu, Ganbare Natuskian, Gnash, LameDS, MAME 2000, Mednafen (NES only), MPlayer, PC-FX Emu, PCSX ReARMed, PicoDrive, Piemu, Pocket CDG, PokeMini, SDL Retro, SMS Plus, ST, SwanEmu, VBA Next, VBEmu). `core/rh_net.c` now uses the firmware's OpenSSL 1.1.1i (TLS 1.2 and 1.3, certificate checks unchanged); PokeMini was then downloaded, installed and launched through the DEV app itself (`docs/HARDWARE_TEST_11.md`). The other Miraheze candidates were not individually retried through the UI. The packages marked **PC-staged** below were fetched by Python on the PC at test time, so their results say whether the app works, **not** that the in-app downloader works; the other packages were fetched by RetroHatch's downloader code run on the PC, and Znax, Rubido and 2048 were downloaded on the device earlier through the app. OpenSSL 1.1.1i is end-of-life: see `docs/NANO_V1_RELEASE.md` blocker 6.
